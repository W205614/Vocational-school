# 职学堂四项后续需求验收与角色复盘

本轮沿用 [上一轮的多角色复盘](product-experience-acceptance.md)，交付于本地 `codex/product-experience` 分支。验收日期为 2026-11-22，使用隔离 Compose、合成账号、模拟支付和真实本地视频。

## 四项交付

| 需求 | 使用流程 |
| --- | --- |
| 历史课程选课资料盘点 | 管理员从「课程管理 → 选课资料盘点」进入，可按课程名称和缺失字段筛选。补录后可在同一窗口按学生端接口核对公开内容。已有报名权益继续有效。与公开稿并存的历史草稿只同步仍等于补录前公开值的字段，保留独立修改。 |
| 上架前生成和预览试看片段 | 管理员在「预览与上架检查」按小节生成、查看状态、预览和重试。启用试看的小节须就绪才能上架。更换媒资会使旧预览签名失效并重新检查。已发布课程的首次试看复用上架前生成的片段。 |
| 已发布作业更正与版本 | 管理员更正标题或说明时填写原因。旧版说明、提交、反馈和生效时间保留。学生和授课教师可查看当前要求，也可在每次提交旁检查对应版本。过期权益只允许查看已提交作品对应的要求。 |
| 教师待反馈作业入口 | 教师登录后在「教学待办」查看阅卷、答疑和待反馈作业，按课程筛选并直达相应提交。反馈后返回原筛选和分页，已处理记录从待反馈列表移出。 |

## 验收记录

最终隔离环境的 14 个容器均健康。7 个应用及网页镜像的运行 ID 与清单逐项一致，5 个 JVM 容器的运行 JAR 哈希也一致。学生端取自 `158495a`，媒资所在的支持服务取自 `f417aa4`，其余镜像取自 `31b888b`。两次定向重建分别修正了试看入口和试看片源查询。支持服务复用了本机已验证的 Linux 媒资运行层，候选 JAR 由本次源码重新打包。

- 隔离数据升级了课程 V004 和学习 V013。升级前后课程资料和作业提交行数一致。3 份已发布作业保留原标题、说明和发布时间，5 份历史提交全部关联到第 1 版。重复执行迁移时应用 0 项。
- Java 定向回归通过 32 项，覆盖课程公开资料、模块访问策略、试看签名和真实 MySQL 的作业版本并发。网关策略另通过 7 项，其中本轮新增用例通过。独立网关调用中有 1 项支付后台权限用例因缺少测试环境变量跳过。
- Linux FFmpeg 下通过 5 项媒资测试，覆盖真实裁剪、独立片段、源文件变更和任务恢复。云媒资对象使用可控夹具，数据库为隔离 MySQL。
- 前端两端构建、类型检查和 40 项单测通过。课程、学习和媒资的 OpenAPI 来自实际启动的应用，重新生成了对应前端类型，现有契约路径均保留。
- 最终 Chromium 同一候选环境通过 4 条场景，零失败、零跳过。游客能查看发布后的课程详情，未报名学生首次试看直接拿到就绪片段。管理端草稿和学生端公开试看都实际解码并推进了播放时间。换源与发布后的旧管理预览地址均失效。
- 管理员补录后，课程继续学习资格保留，公开页显示新资料，独立草稿编辑保留。教师从待办进入指定提交，可核对旧版要求，反馈返回后已处理项移出。学生可从站内信打开反馈并按新版要求重交。购买、完整视频学习、答疑、考试阅卷和定向退款也通过了回归。

录像播放和学习流程覆盖桌面 Chromium 及 390 像素窄屏视口。原始记录保存在本地 `.local/product-acceptance/.local/followup/`，包括 `chromium-final.log`、`backend-result.json`、`migration.json` 和 `runtime-images.json`。

## 角色复盘与后续清单

| 优先级 | 角色 | 观察与下一轮验收条件 |
| --- | --- | --- |
| 高 | 管理员、学生 | 媒资删除仍可将被上架课程引用的视频标记为已删除。删除前展示引用课程和小节，对在售或仍可学习的课程要求先替换媒资或处理课程状态，并复验已报名学生可继续播放。 |
| 中 | 学生 | 作业有更正时，学生需要主动打开详情发现新版。给仍有学习权益且受更正影响的学生发送站内提醒，直达变更内容，支持已读且避免重复发送。 |
| 中 | 教师 | 提交反馈后可以回到原筛选，处理下一份仍需再次选择。教学首页显示三类待办数量和最早等待时间，提供处理下一项，并保持课程范围。 |
| 中 | 管理员、教师、学生 | 作业版本记录可逐个展开，阅读长说明时需要来回核对。增加当前要求和提交所用版本的差异视图，并在两位管理员并发更正时保留尚未发布的输入。 |
| 中 | 管理员 | 新课可逐小节生成试看，已上架历史课沿用按首次请求生成。提供按课程或小节批量预先生成的入口，为已上架旧课补齐片段，并报告每项成功和失败。 |
| 低 | 游客、学生 | 难度、预计学习时长和试看资格集中在课程详情。课程目录应支持直接比较和筛选这些信息，游客与登录学生使用相同口径。 |
| 低 | 管理员 | 盘点可按缺项查找课程。课程量较大时，增加按报名或学习人数排序，并让多人协作时可查看字段级变更时间与操作者。 |

清单基于本轮的合成账号走查和相关代码路径。批量维护和教师连续处理的优先级可在真实教务试用后用工单与使用数据复核。
