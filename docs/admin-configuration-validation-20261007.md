# 课程配置、考试草稿与容器恢复验收（2026-10-07）

本轮继续处理前端体验报告列出的配置表单与草稿缺口，部署到同一套 `tianji-final`，学生端 <http://localhost/>，管理端 <http://localhost:81/>。原业务数据、命名卷与私有配置保留。

## 已修复的用户问题

| 操作 | 已部署行为与验证范围 |
|---|---|
| 配置章节及发布试卷 | 课程、题目、教师和视频按名称检索，20 条分页；多选跨页保留。考试小节来自课程目录，显示章节名称。无需填写内部 ID。 |
| 修改课程资料 | 三级分类、以元编辑价格、介绍及详情、封面预览；本地管理员上传真实 PNG/JPEG，最大 5 MiB。关闭报名的草稿仍可修正内容并保留原截止日期；上架前仍检查报名安排。 |
| 保存关联后刷新 | 视频、题目和教师回显原关联。未保存章节时阻止关联写入；切换课程提示放弃未保存修改。 |
| 跨设备继续考试 | 草稿存入 MySQL；同账号的另一浏览器上下文可继续。输入期间合并同步请求；请求失败时保留本机草稿并允许重试。 |
| 两个设备同时答题 | 版本冲突提示保留本机未同步内容；刷新后仍保持冲突，不能静默覆盖另一设备。主动载入最新草稿先备份本机答案，提供只读备份查看。 |
| 提交及之后的写入 | 提交检查草稿版本；提交后拒绝新的草稿写入。已有提交、评分与学习完成幂等机制保留。 |

本地封面地址不带过期签名，按文件内容 SHA-256 命名，与私有视频目录隔离。公开读取只接受严格的哈希 PNG/JPEG 地址，上传要求管理员；伪装为 PNG 的 SVG 被拒绝，学生上传返回 403。实际图片格式、尺寸与像素数均检查；私人视频仍执行原有归属及签名校验。

## 回归中发现并修复的后端问题

- 课程教师关系复制把教师 ID 带入关系行主键，同一教师关联第二门课程会发生主键冲突。关系行现在使用独立生成的主键；新增回归测试，并由浏览器在多门测试草稿中保存相同教师。
- 课程查询题目分数的 Feign 地址含多余斜杠 `/questions//scores`，实际调用返回 404，导致保存题目后刷新目录失败。改为控制器实际地址 `/questions/scores`，重新打包并验收回显。
- 缺失课程内容行时读取空值导致异常，改为可编辑的空内容；新课程不再生成随机评分。
- 重建考试容器后，网关缓存旧容器地址，健康服务仍出现连接拒绝。网关 Reactor Netty、Java 客户端及两端 Nginx 均使用有界 DNS 缓存；网关连接超时限制为 3 秒，依赖连接失败明确返回 503，用户可重试。
- 新封面最初受媒资服务登录拦截阻挡。显式本地模拟配置只放行独立公开封面目录，保留其他媒资认证。

Java 的 DNS 成功/失败缓存属性以追加安全配置方式设置，不替换系统其他安全属性；参见 [Oracle Java 21 网络文档](https://docs.oracle.com/en/java/javase/21/core/java-networking.html)。网关使用 [HttpClientCustomizer](https://docs.spring.io/spring-cloud-gateway/reference/spring-cloud-gateway-server-webflux/http-client.html) 配置解析器。

## 验收结果

针对最终容器与生产构建执行 Edge Playwright，全程单 worker、无自动重试：**25 项通过、0 项失败**；另外 **13 个执行槽按两端适用范围跳过**。网关连接超时修复后重新创建夹具并完整重跑，最终结果仍全部通过。没有将多次重跑的通过数相加。

完整路径为：实际本地视频上传 → 通过关联选择器发布试卷 → 学生选购、下单及模拟支付 → 发放学习权益 → 播放实际视频并完成小节 → 私人笔记、提问、回答和点赞 → 两个浏览器上下文恢复同一答卷及冲突处理 → 刷新保留冲突并查看本机备份 → 提交并拒绝后续草稿写入 → 授权教师评分为 20 分通过 → 完成考试小节 → 退款审核与权益撤销，保留学习历史。

管理端另验证关闭报名的独立草稿：真实封面上传、内容修正、保留截止时间、禁止过期上架、目录与视频/题目/教师关联、刷新回显；两端 1440/845/390 像素布局以及 390 像素关联选择器无页面级横向溢出。前端类型检查与两端生产构建成功。

后端本轮相关测试 **15 项通过、0 项失败、0 项跳过**：课程截止日期 2、教师关系映射 1、封面校验 3、考试客观评分 1、考试可靠性 4、持久草稿可靠性 4。考试 9 项在真实 MySQL 的独立 `acceptance_exam` 数据库执行：20 个工作线程分别提交 100 次考试创建、100 次重复提交以及 50 次评分请求；10 个工作线程提交 30 个不同草稿的同版本竞争请求（1 成功、29 冲突）。另验证响应丢失重试、归属和提交后不可变。这些是正确性测试，不是 100 并发的吞吐压测。网关另完成 reactor 打包与真实运行故障恢复验证，不计入这 15 项 JUnit 数量。

考试、网关和媒资的 **3 次实际 IP 变化**均验证访问恢复，两端 Web 代理保留运行。单容器重建最初复用 IP，因此再调整两个应用容器的创建顺序，记录真实地址变化；不删除卷或重建基础服务。考试服务停止时返回 HTTP 503；媒资重建后公开封面字节完全一致。报告的恢复耗时仅从容器已经健康后开始测量，不包含启动等待，不能作为故障总恢复时间或可用性 SLA。

## 用户视角与边界

管理员现在可以通过名称完成配置，保存后能够刷新检查；学生草稿不再依赖一个标签页，遇到并发编辑也能保住自己的答案。这些操作比手工填写编号和不明确的“保存成功”更容易理解和复核。

历史课程的真实封面、介绍及报名计划仍需管理员根据原始材料整理；本轮提供编辑入口，不编造数据或自动延长日期。旧版全部页面的逐项等价、生产持续容量、多节点基础设施高可用、真实支付及短信仍需独立验收。

## 复现与恢复

执行顺序和依赖说明见 [根 README](../README.md) 与 [最终部署说明](../deploy/final/README.md)。每次完整购买/考试/退款回归先生成新夹具。考试草稿部署前执行版本化迁移 `tj_exam/V003__exam_drafts.sql`；并发测试在独立 `acceptance_exam` 数据库运行。

恢复测试会停止/重建指定应用，不能用作生产只读巡检。专用 Browser course/free 课程通过正常下架 API 移出学生检索，历史记录不删除；课程配置测试草稿保持未上架，可在管理端复核。原业务课程不在清理范围。

SQL 和私有配置备份留在本机忽略目录。媒资校验清单不包含文件字节，恢复新视频和封面还需保留 `deploy/final/.local/objects`。源码、脱敏报告和截图可以提交 GitHub；账号、令牌、签名密钥和数据库备份不提交。
