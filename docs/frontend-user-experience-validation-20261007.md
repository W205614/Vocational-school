# 前端体验修复与浏览器验收（2026-10-07）

此前新版页面偏向接口验收：侧边导航与数据表占据主要区域，学生考试需要填写内部 ID，购买后的付款入口和处理结果不够明确。与本机保存的原学生门户、管理工作台截图相比，视觉层级和操作引导确实退步。框架与可靠性迁移不能视为前端体验已经交付。

本轮已部署到 `tianji-final`。学生入口为 <http://localhost/>，管理入口为 <http://localhost:81/>。本轮恢复品牌、门户和工作台结构，并实际验证购买、学习、互动、考试和退款。它不是原页面逐像素复刻，也未宣称所有管理表单已达到最终产品体验。

## 观察到的问题与已部署改动

| 用户操作 | 原问题 | 当前行为 |
|---|---|---|
| 浏览课程 | 首页主要是简单表格，缺乏课程信息层级 | 品牌顶部导航、分类横幅、课程卡片、真实讲师/小节/价格、筛选与无结果恢复；缺失封面使用文字封面 |
| 普通窗口浏览首页 | 分类说明换行把横幅撑高，课程列表出现太晚 | 缩短分类区，保留一级分类入口；两端 1440、845、390 像素下无页面级横向溢出 |
| 查看与学习课程 | 内部数据和学习操作混在一起 | 课程介绍、目录、播放器、完成进度与随堂笔记分区；拥有有效学习权限显示继续学习，视频按持久进度恢复 |
| 免费报名 | 已过期旧课程仍能点击报名；报名后提示不清 | 提前显示报名结束，已报名用户保留继续学习入口；当前有效免费课报名成功后刷新仍可学习，权益尚未就绪时明确提示 |
| 下单与付款 | 创建订单后难以接续付款，弹窗切换可能叠加 | 确认选购、优惠方案、订单创建结果、直接付款入口及稍后付款；无支付渠道时明确说明 |
| 取消与退款 | 操作后果和退款原因不明确 | 取消前确认，退款原因必填并说明学习权限影响；退款成功后历史笔记及完成记录保留 |
| 多次打开同一订单付款 | 支付申请锁保留 3 秒，合法重试返回 500 | 服务创建/获取支付链接后释放锁，外部调用期间使用看门狗续租；数据库业务唯一约束及请求防重仍保留 |
| 参加考试 | 要输入课程 ID 与答案编号 | 从已报名课程选择试卷，客观题显示单选/多选选项，主观题文本作答；提交前确认，区分答题中、待评分、通过与未通过 |
| 刷新及登录过期 | 页面报错但不能恢复，草稿归属不清 | 访问令牌可刷新；刷新凭据失效则回到登录表单。同账号重新登录保留当前标签页草稿，换账号清除前账号草稿 |
| 收藏、笔记与积分 | 列表暴露内部 ID 和类型数字 | 显示课程名称、学习状态、积分来源和时间，保留笔记并发编辑冲突提示 |
| 管理工作台 | 导航无分组，首页缺少工作入口 | 分组导航、真实交易指标、订单趋势、课程/考试/订单/退款快捷入口和事件积压提示，不添加随机统计数据 |

## 浏览器及持久化验证

Edge Playwright 针对实际容器运行，单 worker，学生、管理员、教师使用专用验收账号。最终完整回归 **24 项通过、0 项失败**；另 **12 个执行槽按两端适用范围跳过**，不是未执行功能的通过记录。最后仅调整首页 CSS，重新构建两端镜像并复测布局 **6 项全部通过**。类型检查及两端生产构建成功。前端 `npm test` 已改为正确的 Playwright 入口，避免 Vitest 误收集浏览器测试。

完整路径包括：实际本地视频上传 → 管理员发布试卷 → 学生加入购物车、选购、创建订单 → 模拟支付 → 学习权限发放 → 播放实际视频字节并完成小节 → 私人笔记、提问、回答、点赞及刷新恢复 → 考试多选与主观作答 → 草稿刷新恢复 → 提交确认 → 授权教师评分 → 20 分通过并完成考试小节 → 申请退款、管理员审核 → 订单退款完成、视频权限撤销、笔记及完成历史保留。

同一订单 **10 个并发支付申请**全部成功返回同一个链接；数据库核对该订单仅有 **1 条支付记录**。支付相关 Maven reactor **14 项测试通过、0 项失败、0 项跳过**；其中 ProviderSettlementTest 在独立 `acceptance_pay` MySQL 数据库验证 100 个并发支付通知只保存一次支付事实和事件。真实微信/支付宝测试仅显式设置 `TJ_REAL_PAYMENT_TESTS=true` 时启用，本轮未调用真实支付商。

退款后核对：2 条完成小节记录、课表完成数 2、1 次考试通过且得分 20、1 条对应私人视频笔记，均与业务结果一致。本轮这项核对发生在退款及测试课程下架后，不作为新一轮重启恢复试验。

最终 **22 个服务 running/healthy**。9 门专用 Browser course/free 课程通过正常课程下架 API 与事件投影移出搜索首页，保留课程草稿、订单、考试与笔记以便复核；原业务课程未在清理范围内。SQL、私有配置和媒资校验备份保存在本机忽略目录，未删除数据卷。

## 从用户视角的评价与剩余问题

普通学生现在能沿着“找课程 → 报名或购买 → 学习 → 笔记与互动 → 考试”完成操作，不必掌握内部 ID；付款、待评分、报名过期和登录失效也有明确反馈。这些是已经验证的改善。

仍需完善的部分：管理端高级试卷发布及章节配置仍有手工填写课程、小节、题目、教师 ID 的表单，应继续改为关联检索选择器；部分历史课程封面地址不可用、名称或介绍不完整，需要内容数据整理；部分旧课程报名日期已过期，应由管理员按实际课程安排调整。本轮保留事实并提示结束，未伪造有效日期或新课程内容。草稿只保存在当前浏览器标签页，不支持跨设备恢复。尚未验证原版每一个页面的功能与视觉一一对应，也未用此回归替代性能压测或生产容量测试。
