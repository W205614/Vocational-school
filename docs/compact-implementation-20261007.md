# 合并部署、安全与恢复实施记录

主要源码和部署改造已经落地，并在独立的 `tianji-compact` 环境完成本机回归。历史环境没有切换。正式性能对照和历史数据切换验收仍未完成，因此不能宣布整个切换计划通过验收，也不能宣布内存已降低至少 20%。

本次工作树以 `e1d4d8c` 为起点，尚未提交或推送。原有 `.gitignore` 修改及 `deploy/docker/` 迁移内容保留，本轮没有改动它们。原 `tianji-final` 的 22 个容器最终均健康；新部署为 11 个健康容器，其中 5 个 Java 应用、2 个网页和 4 个基础设施服务。

## 已落地的改造

| 范围 | 实现与边界 |
| --- | --- |
| 会话闭环 | 每次登录建立独立会话，保存刷新 JTI 的哈希，刷新事务加锁并支持 10 秒并发重试窗口；重新读取账号状态、角色和安全版本；支持查询及撤销自己的会话。账号禁用、改密、角色变化由数据库触发器更新安全版本，网关有效会话最多缓存 5 秒，认证依赖故障时拒绝放行。 |
| 入口与内部权限 | 显式的方法/路径清单及默认拒绝，检查版本化接口和管理员别名覆盖；网关清除外部身份、服务凭证与转发身份头；内部模块入口要求服务凭证，用户登录查询、批量用户查询等隐藏接口也检查服务身份。 |
| 登录保护 | 可信直接连接来源 IP 的分钟限流、账号失败次数和短暂锁定；使用 429 和 Retry-After；区分账号错误与下游不可用，避免因依赖故障锁死账号。当前仅面向回环入口，未来公网代理链需要另行配置可信代理。 |
| 数据库权限 | 12 个业务库各自使用只有所属库 SELECT/INSERT/UPDATE/DELETE 的运行账号，迁移独立使用管理账号；积分赛季归档表由迁移预建，运行代码不再申请 DDL。旧历史部署的 root 配置没有被替换。 |
| 管理与教学 | 管理员操作审计记录操作者、角色、路径、请求编号和结果，异步操作关联最终状态，增加查询页面；教师待评分列表增加分页、课程与学生筛选和课程归属条件。 |
| 应用合并 | identity(auth/user)、commerce(trade/pay/promotion)、education(course/learning/exam/remark)、support(media/search/message/data)，加独立 gateway。保留 12 个业务库和业务模块各自的事务、任务、Outbox、Inbox 及幂等协议。 |
| 模块隔离 | 一个宿主 HTTP 服务器，多套独立 Bean 容器、Mapper、数据源和事务管理器；禁止 Bean 定义覆盖；内部加模块前缀，外部 `/api/v2` 路径与响应保持兼容。同应用使用带身份及上下文保护的内存 MVC 适配器复用模块接口，跨应用继续 Feign。 |
| 资源保护 | 有界操作/Outbox 执行器、网关准入和队列、每券并发限制、同应用调用并发限制、上传与图片解码并发限制；保留库存行锁与事务校验；共享同宿主的 Redisson 连接资源，降低空闲轮询频率。 |
| 干净交付 | 版本库内结构基线、权限目录、合成演示数据和配置模板，自动生成随机密钥及受限账号；不依赖本机旧 JAR 或旧业务数据库；拒绝无初始化日志的已有业务库。 |
| 备份与恢复 | UTC 时间戳目录、临时包校验后发布、多恢复点保留；SQL、触发器、私有配置、签名密钥、实际媒资文件、Redis DUMP/到期时间、停写后的 RabbitMQ 数据目录及哈希清单。恢复只使用新目录和未使用的独立项目，禁止覆盖非空 Redis 和错误卷归属。 |
| CI | 加入会话、登录分类、权限清单、考试草稿、封面和课程配置测试，新增合并环境启动、浏览器主流程、审计与 Redis 恢复检查；只上传不包含凭证的结果摘要。本次修改后的 GitHub CI 尚未远程执行。 |

合并的好处是减少启动应用和固定框架开销，代价是扩大一个进程失败时影响的模块范围。当前仍是单机隔离部署，未引入真实支付、多节点高可用、Kubernetes、服务网格或多租户。

回归另发现并修复课程列表加载期间丢失筛选点击的问题。课程查询现在串行执行并合并为最新筛选条件，测试主动延迟首次查询，验证加载期间点击分类确实生效。

完整浏览器业务路径包括购买、真实本地视频上传与播放、学习、笔记问答、考试草稿版本冲突、教师评分、退款及退款后的考试历史。它不代表每一个后台 CRUD 组合或外部供应商接口均被回归。

此次停写恢复点的 Redis 业务键数量为 0，所以另用两套独立 Redis 构造非空、多类型和二进制数据验证。消息队列恢复验证包含数据目录和后续业务消息处理，没有专门构造带大规模未处理积压的恢复故障。恢复使用独立数据库、卷、目录和端口，但仍在同一个 Docker 主机上；换机器恢复还需要保存或取得记录的原镜像，当前备份未包含 Docker 镜像字节。

首次恢复尝试因镜像向新 RabbitMQ 卷复制初始化文件而被空卷检查拒绝；没有覆盖任何已有数据。现已使用 `nocopy` 空卷并拒绝复用已有恢复项目，重新演练通过。失败演练的目录和卷保留，成功演练环境停止，源环境恢复原来运行的服务。

## 性能采样与未完成验收

50 个独立合成学生，10 秒预热后执行 60 秒负载，250ms 思考时间，90% 常规查询、10% 异步笔记写入；统计收尾和采集后总耗时约 64.51 秒。运行期间没有同时执行 Maven 构建或浏览器回归，原部署及其他既有容器仍常驻。

| 指标 | 次数 | P95 | P99 |
| --- | ---: | ---: | ---: |
| 常规查询成功 | 6525 | 198ms | 422ms |
| 异步写入接受成功 | 701 | 310ms | 710ms |
| 异步完成成功，含接受及轮询时间 | 701 | 2015ms | 2314ms |

此窗口没有业务拒绝、准入拒绝、系统错误或传输错误；采集 5 组资源样本，13 个模块的指标可用，没有触发脚本告警。它只说明当前数据和负载下链路可运行，不能代表领券热点、考试高峰、完整交易容量或长时间稳定性。

**尚未完成的切换验收：**

1. 同机器、相同业务代码及镜像版本、同份数据，合并前后各执行 10/50/100/200 并发、每档 30 分钟、重复三次，采集尾延迟、错误、资源、数据库等待和积压；完整对照至少 12 小时，另加准备时间。
2. 比较预热后的稳态 Java 内存、空闲 CPU、连接数和启动时间；内存降低至少 20% 尚未取得正式实测证据。
3. 以历史数据副本完成分批兼容回归及积压核对，再安排历史实例停写和入口切换。本次只验证了合成数据及其新产生的订单、学习、考试等历史，没有将原历史库迁到新部署。
4. 修改后的远程 CI 成功记录，以及专门的待处理事件积压恢复演练。

`release_gate.py --historical` 本次实际返回非零：功能、安全、审计和恢复检查为 true，正式性能和历史数据一致性为 false。没有执行原入口切换，也没有用旧备份覆盖任何新业务数据。回退规则是保留当前数据，切回兼容镜像/路由或进行增量回迁，不能直接回灌切换前备份。

Elasticsearch 保持 7.17.29 的本机隔离配置，其支持版本升级仍为单独阶段；当前不宣称生产可用或互联网部署验收完成。
