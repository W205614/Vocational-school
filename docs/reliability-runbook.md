# 可靠事件与发布运维

## 处理语义

数据库业务变更与 Outbox 在同一事务提交；消息 ID 在重投时保持不变。投递任务取得数据库租约，使用 RabbitMQ correlated confirm、mandatory return 和持久消息，只有确认成功且未退回才标记 SENT。确认丢失、进程退出和不可路由都保留持久记录并退避重试。交付语义为至少一次；消费者用业务事务中的 Inbox 唯一键去重，业务自身仍有状态 CAS/业务唯一约束，不能宣称传输层恰好一次。

202 表示请求已持久化，只有操作状态 SUCCEEDED 才表示业务完成。同用户、操作类型、Idempotency-Key、相同公共请求返回原 operation；不同请求返回 409。服务端补充的课程/试卷元数据不改变请求哈希。未知失败保留重试，明确业务失败展示原因。

学习进度快照保存在 MySQL，moment 单调合并、版本处理，视频完成与课表计数同事务 CAS。考试只有全部评分完成且通过才发完成事件。权益按订单条目保存，退款撤销相应条目，历史课表/笔记/答题保留。取消后的有效支付保存事实和人工工单；人工操作必须基于实际支付凭证，系统不会自动恢复订单或退款。

## 失败与重放

管理员管理端“可靠性与补偿”能查看各服务的 Outbox、操作失败、消费失败、支付冲突、搜索投影、媒资清理和通知投递。查看失败原因与原始业务状态后再重放。重放采用当前版本 CAS，过期版本返回 409；事件保持原 ID，消费/业务去重防止再次发券、积分或发课。永久业务失败不能通过重放变为成功。

应用重启后租约超时的任务可再次竞争，多实例使用数据库锁/条件更新。单机验收只能证明应用层故障恢复，不能证明 MySQL、Redis、RabbitMQ、ES 本身的多节点高可用。积压、DEAD、消费者失败、资源队列告警应同时关注业务工单和队列延迟。

权限变更先保存数据库和事件，消费事件在数据库 guard 下读取当前全量权限，再一次性原子发布不可变 Redis 快照。请求读版本一致的快照；缓存不可用或陈旧时拒绝授权。网关清除外部身份/内部调用头，验证 JWT 后以内部凭证向服务转发身份。内部令牌须由密钥管理器分发且阻止外部访问后端端口。

## 发布门禁与回退

1. 备份真实库/对象配置并验证恢复，记录版本、数量、关键关系、当前未提交改动。历史重复发券、学习记录、点赞、购物车、权限、有效退款先人工核对，迁移遇到重复即停止。
2. 在独立环境按校验和顺序执行 SQL，完成关系核对、EXPLAIN、全模块构建启动、真实数据库/消息测试、浏览器路径和故障恢复。
3. 配置真实第三方渠道，明确环境标志。关闭模拟，配置生产 TLS、鉴权密钥、内部令牌、JWK、供应商回调验证和可达地址，实测支付/退款/短信/视频。不要自动回退模拟成功。
4. 维护窗口停止旧写流量与后台任务，清空或归档旧待处理事件，执行迁移和权益/销量投影重建，核对库存、订单金额、有效权益与投影，再切换。
5. 保留旧版本和已验证备份回退入口。新版本写入后不能简单执行反向 DDL/删除新表，应停写、保存新事实和事件，恢复快照并核对窗口增量后再决定回退。支付事实和人工工单不可丢失。

当前本地验收没有切换原部署，没有远程发布，也没有验证多节点 HA 或真实供应商。CI 已添加，但只有实际运行通过的本地门禁能作为当前证据。14 个应用 Linux 镜像逐个启动检查、两个 Nginx 镜像的完整浏览器路径已通过；跨服务后台仍使用固定宿主机 JAR，尚未同时运行完整应用容器栈。最终验收报告列出实际通过项和剩余边界。
