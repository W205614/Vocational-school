# 2026-10-20 各角色模拟使用与体验修复

本批在现有 `tianji-compact` 本机演示部署检查游客、学生、教师和管理员流程。支付与短信仍为本地模拟。测试前完成完整备份并校验，恢复原运行状态；保留原数据库、媒资、命名卷、历史备份及其他项目容器。

## 发现与修复

| 场景 | 原问题 | 修复后的行为 |
| --- | --- | --- |
| 学生个人页面 | 收藏请求未完成时进入笔记，新请求被 busy 防重复逻辑丢弃，旧列表写入新页面 | 合并等待中的最新查询，旧响应不覆盖当前页面 |
| 学生交易页面 | 购物车切订单、可领券切我的券存在同样的请求丢失和数据串页 | 加载结束后补发当前页面／标签查询，保留写操作防重复行为 |
| 个人设置 | 改密成功后两个密码输入仍保留，下一次改昵称又提交原密码 | 保存成功后清空密码输入，后续资料修改不重复改密 |
| 教师评分入口 | 默认显示空列表但未查询待评分答卷 | 进入页面自动加载当前教师可评分的记录 |
| 教师评分提交 | 未填写分数会被当作 0 分，完成评分后待办仍保留 | 要求显式填写范围内整数，允许明确填写 0 分；完成后刷新待办并校正越界页码 |
| 教师答疑 | 只能看到问题标题；另一问题可能残留上一题的回复与草稿 | 展示详细问题描述，切题清理旧内容；回复加载失败时禁止发布并提供重试 |
| 教学学情筛选 | 从高页码切换课程或筛选学生仍请求旧页码，容易误判没有记录 | 学习、考试及问答分页重置为第一页 |

改动限定在四个前端页面及两份定向浏览器测试，没有修改后端业务、权限规则或全局写操作防重复逻辑。

## 验证证据与边界

- 首轮选择 28 个角色执行槽：16 通过、10 个角色不适用跳过、2 个因并行测试清理共用 trace 目录而中断。两个中断用例是购买至退款闭环、课程筛选与空态恢复，不能把首轮记为全部通过；后续使用独立输出目录补验。
- 学生端四个新增回归在旧容器全部失败，在修复源码全部通过；教师端自动加载、答疑描述两个旧容器回归失败，修复源码的三个回归全部通过。教师评分写入和异常答疑响应使用浏览器拦截，避免对已有真实答卷打测试分数。
- `npm --prefix frontend run typecheck` 返回 0。本地仅验证本次修改与直接关联行为，完整后端及浏览器门禁交给最终提交的 GitHub Actions。
- 首轮覆盖账户与资源页真实读取、登录错误恢复、游客课程浏览、学生学习／积分／错题入口、教师入口与角色隔离、管理表单，以及双端 1440／845／390 像素布局和刷新。未发现阻断性的页面加载错误或横向溢出。

本机脱敏日志、截图、失败复现及部署快照位于被忽略的 `deploy/compact/.local/role-audit-20261020/`。账号、密码、备份包及完整 trace 不提交 GitHub。

## 使用体验判断

桌面与手机的主要入口可用，导航滚动保持在各自区域内。本次影响更集中在慢网切换、教师待办反馈、评分误操作和答疑上下文，修复后减少了手动刷新、空列表误判及跨题内容混淆。

当前演示环境已累积多批明确标识的合成课程，首页首屏数据不代表正式课程运营内容；本批保留这些业务与验收历史，没有为美化截图删除数据。真实第三方支付、短信、持续容量和多节点可用性不属于本次验证结论。

部署仅重建有改动的学生／管理网页镜像与容器，保留原网页回退镜像。后端继续使用此前 `add8e09ec9a275c90d59b8acff4e4416d6716b4a` 构建的镜像；本批最终网页源码提交、容器验证及精确 SHA 的 CI 结果在交付回复中提供。
