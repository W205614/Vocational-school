# 本机合并部署与验收

本手册说明本机部署、回归、备份恢复与性能工具的操作。默认运行组为 `tianji-compact`，共 11 个业务／基础设施容器和 3 个本机监控容器，使用合成演示数据与模拟支付，所有入口绑定 `127.0.0.1`。既有数据、配置及媒资保留。当前构建来源见本机 `.local/package-source.json`、`.local/images.json`，最近维护结果见仓库根目录 `.local/defense-fixes-20261030/`；[历史部署记录](reports/current-deployment-20261026.md)不作为新版本重新验证的证明。外部旧生产正式导入及割接尚未验收，其他项目不在操作范围。

功能与架构概览见 [项目 README](../../README.md)；当前部署、真实课程专项和商业化代码的证据范围集中在 [交付索引](reports/README.md)。

本机真实教学视频的清单、三文件隔离演练、可重入全量导入及导入窗口关闭方法见[受控本地课程视频导入](LOCAL_COURSE_IMPORT.md)。视频字节与私有清单保存在 `.local`，不提交 Git；全新初始化不会自动获得本机素材。服务端使用 `ffprobe` 读取真实时长，`support` 构建时安装 FFmpeg 包，首次构建需要访问发行版软件仓库。脱离容器运行媒资模块时，需安装 `ffprobe` 并配置 PATH 或 `tj.local-storage.ffprobe-command`。

媒资复制与探测默认分别最多 2 路（`tj.local-storage.upload-concurrency`、`probe-concurrency`，范围 1～4），单次探测默认 30 秒（`probe-timeout-seconds`，范围 1～60）；饱和返回 429，异常释放许可。签名默认 600 秒（`signature-ttl-seconds`，范围 1～600），缩短仅用于隔离过期验证。学生页面续签保留播放状态并重新检查权益，新的计时会话直接使用媒资毫秒时长，目录的整数秒仅用于展示。这些限制是本机资源保护参数，不是容量证明。

本机自动备份已停用，不保留有效本地恢复集或镜像离线包；业务数据卷、媒资与配置继续保留。既有部署升级、备份工具和本机告警见[稳定性与运维说明](../../docs/stability-operations.md)。不要对已有业务库重复执行首次初始化。

## 结构

| 应用 | 原模块 | 默认端口 |
| --- | --- | --- |
| identity | auth、user | 24001 |
| commerce | trade、pay、promotion | 24002 |
| education | course、learning、exam、remark | 24003 |
| support | media、search、message、data | 24004 |
| gateway | 网关 | 24310 |

| 入口 | 默认本机地址与页面 |
| --- | --- |
| 学生门户 | `http://127.0.0.1:24500/`；游客选课 `/`、课程 `/courses/:id`、学习 `/learning`、积分 `/points`、复习 `/review`、笔记 `/notes`、考试 `/exams`、结算 `/cart` |
| 教师／管理端 | `http://127.0.0.1:24501/`；授课学情与答疑 `/teaching`、授权评分 `/exams`、管理员赛季奖励 `/seasons` |
| API 网关 | `http://127.0.0.1:24310/api/v2/` |

游客仅能读取公开课程介绍和目录；登录后回到原操作，个人数据和收费媒体仍由后端校验。教师授课权限和评分权限独立。业务仍使用原来的 12 个数据库。每个模块有独立 Spring Bean 容器、Mapper、连接池、事务管理器、任务和消费者，共享宿主的 HTTP 服务器；禁止 Bean 定义覆盖。普通业务 JAR 由四个启动模块组装。默认 Maven 构建仍保留独立应用，`-Pcompact` 构建合并应用。compact 与媒资 worker 的配置已禁用 Nacos，相关交付包不包含 Nacos 客户端和 starter；需要 Nacos 的独立部署须另行验证客户端依赖安全及服务连接。

内部路由为 `/_modules/{alias}/...`，必须提供服务凭证。网关保留 `/api/v2` 路径、响应结构及角色检查。优化分支使用标准 Feign HTTP：同宿主调用回环地址，跨宿主调用服务地址，连接超时 1500ms、读取超时 5000ms。身份、请求 ID 与调用深度随内部请求传递；深度超过四层时拒绝，按深度保留内部处理容量。模块之间仍执行各自事务和幂等、补偿协议，不将远程业务隐式并入同一事务。

## 干净启动

实际生效的 Compose 为本部署被忽略的 `.local/compose.runtime.yaml`；版本库中的 `compose.yaml` 仅作公共模板。所有 Python 运维入口使用统一解析器并显式指定项目目录，因此配置移入 `.local` 后，媒资、密钥及配置的相对挂载仍相对于本部署目录。

旧版本升级前，先在原 checkout 保存当前生效配置；此步骤不依赖新版本脚本：

```powershell
if (Test-Path deploy/compact/.local/ops-status/resume.json) { throw '先在原版本恢复未完成的备份，再更新源码' }
New-Item -ItemType Directory -Force deploy/compact/.local | Out-Null
if (-not (Test-Path deploy/compact/.local/compose.runtime.yaml)) {
    Copy-Item -LiteralPath deploy/compact/compose.yaml -Destination deploy/compact/.local/compose.runtime.yaml
}
```

确认私有副本存在后再更新源码，保留 `.env`、`.local` 和卷。新版本直接采用该私有文件；不要把更新后的公共模板复制覆盖它。`setup.py migrate-runtime` 用于公共文件仍是旧生效配置时的解析等价核对，不适用于已将公共文件恢复为模板后的再次迁移。升级、搜索切换和备份只更新私有运行文件；旧备份包中的配置仍命名 `compose.yaml`，恢复时写入新的私有运行位置。过时批次的专用探针已移出工作目录；恢复验收使用下文当前工具。

需要 Java 21、Maven、Node.js 22/npm、Python 3.12+、Docker Compose 和可用镜像源。Windows PowerShell 中请确认这些命令已加入 PATH。

```powershell
python -m pip install -r deploy/compact/requirements.txt
npm --prefix frontend ci
python deploy/compact/setup.py prepare
python deploy/compact/setup.py init
python deploy/compact/setup.py build
python deploy/compact/setup.py up
python deploy/compact/prepare_search.py
python deploy/compact/rebuild_search.py
```

初始化只使用版本库中的结构、权限目录和合成演示数据，不读取本机历史 JAR 或旧用户订单。遇到已有业务库但没有本初始化器日志时直接拒绝覆盖。`.env`、签名密钥、账号、配置、对象和报告保存在被忽略的 `.local` 中；演示登录账号查看 `.local/accounts.json`，不要提交该文件。每个运行账号只有所属库的 DML 权限，DDL 由迁移入口执行。

Linux 构建使用当前非 root 用户的 UID/GID 创建镜像用户，匹配媒资 bind mount 的所有者，避免上传文件和宿主备份互相失去权限；Windows 或 root 执行构建时仍使用非 root UID/GID 10001。恢复到不同 UID 的 Linux 主机时，需要单独核对对象目录与镜像用户的权限。CI 失败诊断只导出已脱敏的状态和日志片段，私有配置不上传。

升级现有库时通过 `python deploy/compact/setup.py migrate` 执行版本化增量迁移。新赛季自动创建月份记录，沿用统一的持久积分事实、榜单投影和最终快照，不为新增月份动态建表，也不要求每月运行迁移。旧月份只读，迁移不补造历史积分或奖励；运行账号仍没有建表权限。数据库触发器更新账号安全版本；改密、禁用或修改角色后，网关最长缓存 5 秒，旧会话随后失效。刷新必须携带 `audience=student` 或 `audience=admin`，会话可独立撤销。

已有部署升级时，在完成停写备份、提交源码及迁移后，启动新版应用前运行：

```powershell
python deploy/compact/client_contexts.py
```

它根据当前源码补入缺失的 Feign context，从已有对应服务配置复制 URL 和超时等值，不覆盖已存在的 context／自定义配置，不重建 Compose。工具先验证全部待更新模块，原始配置保存在本部署的私有 `.local/client-context-sync/<UTC批次>/`；该目录不提交 GitHub。不要用重新运行 `setup.py prepare` 替代这一既有部署配置补全步骤。

操作独立副本时先设置对应 `TJ_COMPACT_HOME`、`TJ_COMPACT_PROJECT` 和 `TJ_COMPACT_PORT_OFFSET`，确认同步目标属于该副本；默认命令目标为 `deploy/compact`。配置同步后重新绑定最终配置指纹及运行镜像，不把同步前指纹当作新版部署证据。

单批启动可用 `setup.py up --group identity`，随后 commerce、education、support、gateway。所有合并组件都应通过验收后才允许历史入口切换。

## 回归

```powershell
python deploy/compact/check_policy.py
python deploy/compact/run_backend_tests.py
# 已准备独立回归库时，也可直接选取集中维护的清单：
python deploy/acceptance/run_tests.py --suite regression
python deploy/acceptance/run_tests.py --suite core
npm --prefix frontend run typecheck
npm --prefix frontend run test:unit
python deploy/compact/security_smoke.py
# 安全测试会短暂限制生成的学生账号，等待 32 秒再运行浏览器。
Start-Sleep -Seconds 32
cd frontend
npx playwright install chromium
cd ..
python deploy/compact/run_browser.py
python deploy/compact/audit_smoke.py
```

数据库测试仅初始化 `acceptance_*` 专用库；完整后端入口还串行执行真实套接字与模块准入测试，要求指定用例全部执行且没有跳过，失败日志按次保留。普通浏览器每次新建明确标识的合成夹具并重建搜索投影；验证游客选课及登录回跳、购买、媒资、周计划、签到、积分、笔记问答、考试草稿冲突、评分、退款和退款后的考试历史。高级错题、历史榜展示、成就和奖励链路使用独立夹具，仅在明确隔离副本或临时 CI 启用。失效权益保留本人历史读取，页面解释原因；开始考试、保存草稿及收费视频继续受权益限制。管理订单分别显示课程快照和学员，回归同时核对接口字段与表格。管理端新增按模块查询的操作审计；教师待评分列表有分页及课程、学生筛选。审计的异步操作与操作记录关联，`ACCEPTED` 不等于业务成功。

完整、核心和传输清单统一在 `deploy/acceptance/test_suites.py` 维护。`--suite` 与显式 `--tests` 互斥；无参数仍仅运行原 `tj-common` 两项，显式 `--modules/--tests` 保持兼容。真实支付与短信测试仍需分别显式设置 `TJ_REAL_PAYMENT_TESTS=true`、`TJ_REAL_SMS_TESTS=true`，本轮未启用。

重复浏览器运行会累积业务数据。结算返回全部可用券，展示名称、规则及本人券的实际到期时间；最多选择 6 张参与方案计算，也可以不用券。持券超过 6 张时提示选券，显式无券仍可购买，优惠计算超时或不可用时显示原因提示。客户端限制选择数量，服务端再次校验归属及最多 6 张的边界，不能把重复验收累积的券删除后宣称解决问题。

独立恢复先核对原备份内容与原账号历史，再使用独立合成账号验证新增业务，保留所有历史记录。复习掌握状态的接口使用布尔值，版本号按原值回传；浏览器覆盖未掌握→已掌握→重新复习，并核对跨设备读取和原考试成绩不变。当前保留记录的测试来源与边界见 [交付索引](reports/README.md)。

CI 的 `backend`、`frontend`、`compact-browser` 分别验证后端与部署工具、双端类型／单元／构建、合并启动及实际浏览器流程。高级回归在临时环境创建合成历史展示及待发请求，真实应用完成考试、学习事件、扣库存发券和回执；不直接伪造发券成功。自然月结算另由可控时钟及真实数据库边界测试验证，不修改主机时间。

当前镜像源码与核对范围见[本机部署记录](reports/current-deployment-20261026.md)。CI 按最终推送提交的准确 SHA 核对，不以动态分支页面或旧版本结果代替。

## 备份与独立恢复

```powershell
python deploy/compact/backup.py
python deploy/final/final_backup.py --verify <完整备份目录>
python deploy/compact/restore.py <完整备份目录> --home <新的空目录> --project tianji-recovery-demo --offset 1000
# 自动演练、保存验收结果，并恢复原来运行的服务：
python deploy/compact/rehearse_recovery.py <完整备份目录> --pause-source
# 单独验证非空 Redis 的二进制、多种类型、TTL 及覆盖拒绝：
python deploy/compact/redis_roundtrip.py
```

默认备份暂停该项目的应用和网页，完成后恢复之前运行的服务，并等待健康检查通过；恢复启动失败时命令返回非零。SQL 含表、数据、触发器；包内还包括私有配置、签名密钥、实际媒资字节、Redis DUMP 及绝对到期时间、停写后的 RabbitMQ 数据目录、镜像标识、表行数和 SHA-256。校验通过后才将临时目录发布为不可变 UTC 时间戳目录。当前镜像包也验证成功后，只保留最新受管完整恢复点，将旧受管备份移入 Windows 回收站。失败目录保留供排错；新包失败不会处置上一份完整备份。

`--online` 只提供部分在线备份，不能作为完整跨资源恢复证据。恢复程序要求新的空目录和从未拥有资源的 recovery 项目，禁止镜像向消息队列恢复卷自动复制初始化内容，拒绝非空 Redis、错误卷归属和镜像标签漂移；首先核对每张表的精确行数、内容校验和及每个媒资文件哈希，再重建搜索投影、读取原业务历史并在恢复环境运行新的浏览器完整流程。恢复环境会占用额外资源，可以先暂停自己的 compact 项目；不得操作其他项目。

不要使用 `docker compose down -v` 清理有数据的部署。恢复失败时保留恢复目录和卷；重新演练使用另一个新的目录、项目名和未占用端口。

## 性能验证

单机演示默认将普通 API 与视频传输分别限制为 160／16 个并发请求，媒体每可信客户端 IP 最多 4 路、签名校验后每位学生最多 2 路。普通接口使用 Redis 原子请求额度，登录业务按身份、游客查询按可信 IP 计算，超限返回 429 和重试提示；登录失败保护另行生效。这些是可调整的资源保护参数，不是吞吐或容量测试结果。

`demo_release_gate.py` 用于核对受影响后端测试、角色体验、恢复及增量迁移、历史数据保留和镜像来源，并明确记录性能未验收。运行此工具需要对应批次的实际证据；本次文件与资源清理没有重新执行这些业务验收，也不沿用旧门禁结果作为当前通过证明。

以下为保留的性能协议与工具，**不属于当前功能交付的通过证明**；200 并发容量和 RSS 降低 20% 均未完成当前版本验证。当前协议与证据边界见 [性能工具说明](OPTIMIZATION.md)。

```powershell
python deploy/compact/load_fixture.py
python deploy/compact/load_test.py --users 50 --seconds 60
```

上面的旧负载入口只覆盖查询与笔记，作为链路诊断保留，不作为本轮正式验收。当前正式协议为 `perf-3h-v1`，入口是 `mixed_load.py`，由 `run_baseline.py` 和 `run_post_measurements.py` 串行编排冻结的测量环境。每种配置按 10/50/100 并发各 300 秒、200 并发 600 秒三轮执行，合计 45 分钟；修复前独立、修复前合并、修复后独立、修复后合并共 180 分钟正式采样。初始化、快照恢复、串行登录、每轮 300 秒查询预热、调参诊断和失败重测另计。

总并发包含全部业务用户，固定随机种子 20261007、250ms 思考时间；查询/笔记/进度/考试评分/购买支付退款/热点领券比例为 50/10/15/10/10/5，低并发档每类至少一人。教师、管理员动作在所属流程内串行执行，不增加独立业务用户。每轮恢复基础快照，使用足量合法夹具，测量期间不得运行构建、浏览器、恢复演练或镜像下载。

每个阶段的独立与合并部署须使用相同业务源码、基础快照和基础设施镜像。200 并发三轮中，每类查询 P95 ≤500ms，每类命令机器处理 P95 ≤3s，成功样本至少 100；预热及正式阶段的非预期拒绝、429、5xx、超时都会导致验收失败。RSS 包含全部业务 Java 服务和网关，取每轮最后六分钟的时间中位数，再取三轮中位数；合并部署须相对同阶段独立部署降低至少 20%。持续增长、采样不足或背景干扰均不能判定通过。

同时保留整套环境资源、业务吞吐、连接等待、SQL/锁等待、队列及 GC 证据。默认候选为连接池 8、操作与调度线程 2、轮询间隔 250ms，仍需正式验收；工具保留 4/8、1/2、750/250ms 的有界候选。12 个业务连接池加 16 个观察连接、16 个控制预留，连接预算为 128，不超过数据库上限 160。观察查询取消冗余逐次 ping，连接等待与所有失败仍计入结果，并单独记录观察耗时。修正测量工具后使用新批次重测四组，拒绝混用旧指纹报告。不得取消业务校验、无限扩容或排除失败样本。该协议只验证本机合成数据的短周期容量，不证明长期无泄漏、无慢性积压、多节点高可用或真实支付。原始报告绑定要求与未验证范围见 [性能工具说明](OPTIMIZATION.md)。

## 切换与回退约束

`python deploy/compact/release_gate.py --scope functional` 要求同批次的后端、浏览器、安全、审计、非空 Redis、完整独立恢复、搜索回退和既有记录保留证据；提交、镜像、配置或基础快照不匹配，以及缺失、陈旧或失败的证明均返回非零。具体变更仅验证修改及直接影响链路，未执行整套门禁时不得宣称其通过；完整 CI 单独核对最终提交。

默认 `python deploy/compact/release_gate.py` 保留完整 `perf-3h-v1` 门槛；`--historical` 另要求原历史数据一致性证据。当前功能交付不代表原离线历史数据可以直接切换，不自动变更原入口。性能与历史证据不得手填“成功”绕过验证。安全检查或高频浏览器登录后应等待登录窗口自然到期再开始下组检查；不要删除限流键或关闭防护。

历史切换必须先在独立副本验证迁移和接口一致性，再安排停写窗口：停止旧入口的写请求、旧后台任务及消费者，检查数据库操作/Outbox 和 RabbitMQ 积压，取得一致备份，恢复到目标，完成行数、媒资和关键业务校验后切换路由。保留原镜像及配置。新实例发生写入后，回退必须让旧代码兼容读取当前数据或先做增量回迁；禁止用切换前备份覆盖新订单、评分、退款等数据。新旧消费者不能同时消费同一业务队列。

当前入口为最终个人演示部署；原入口已停用，原历史数据保留离线。容器退役不等于历史数据迁移，历史切换门禁仍有效。默认搜索为 Elasticsearch 9.5.5，7.17.29 兼容版本仅用于本机隔离回退验证；每次切换暂停本项目写入及相关消费者，创建新卷，从当前 MySQL 重建并核对元数据、销售数和财务事实，再恢复服务。真实渠道、多节点高可用与目标云环境仍需独立验收；仓库中的商业部署工具不表示本机已完成这些验证。

本机使用模拟支付，真实支付适配器未启用。真实渠道使用受保护的独立配置与有效凭据，按[生产部署说明](../production/README.md)和[商业化运行手册](../../docs/commercial-ha.md)分别验证签名、回调、结算与退款；本机启动或合成测试不替代供应商验收。

## 学习体验升级与隔离迁移演练

学生端提供游客选课、学习计划工作台、可搜索的时间点笔记、月赛季与成就、错题复习；教师与管理端提供授课学情、答疑及赛季奖励管理。学习目标统一为 1–50 小节／周，答卷全部评分完成后才显示快照答案和反馈；错题复习不改变原成绩。权益失效后历史保留，收费媒体和业务写入仍受限制。

待完成考试按当前有效权益课程中“每个考试小节的最新已发布试卷”计数：尚未通过，且没有待评分答卷；包括尚未开始、作答中和未通过可重考。待评分数量单列。未读互动通知统计本人未读、已发布且未过期的互动消息，包含课程回复、教师采纳和公共互动，按完整数据计数并避免公共通知重复计入。任一提醒依赖不可用时，该项显示未知及原因，可独立重试；不能用 0 代替失败，也不影响已有课程和学习计划展示。

本人赛季奖励按全部月份分页查询，奖励标签、页码和榜单月份保存在 URL，刷新可恢复；榜单月份不冒充奖励列表的月份过滤。管理员配置奖励优惠券时，可按名称进行服务端查询并逐页加载，不限于本地前 100 张；已有选券保留名称，失败时禁用陈旧选项及保存，重试继续原查询。
